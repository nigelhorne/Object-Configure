   57: =head1 SYNOPSIS
   58: 
   59: The C<Object::Configure> module is a lightweight utility designed to inject runtime parameters into other classes,
   60: primarily by layering configuration and logging support,
   61: when instatiating objects.
   62: 
   63: L<Log::Abstraction> and L<Config::Abstraction> are modules developed to solve a specific need,
   64: runtime configurability without needing to rewrite or hardcode behaviours.
   65: The goal is to allow individual modules to enable or disable features on the fly,
   66: and to do it using whatever configuration system the user prefers,
   67: and to separate run-time configuration from code.
   68: 
   69: Although the initial aim was general configurability,
   70: the primary use case that's emerged has been fine-grained logging control,
   71: more flexible and easier to manage than what you'd typically do with L<Log::Log4perl>.
   72: For example,
   73: you might want one module to log verbosely while another stays quiet,
   74: and be able to toggle that dynamically - without making invasive changes to each module.
   75: 
   76: To tie it all together,
   77: there is C<Object::Configure>.
   78: It sits on L<Log::Abstraction> and L<Config::Abstraction>,
   79: and with just a couple of extra lines in a class constructor,
   80: you can hook in this behaviour seamlessly.
   81: The intent is to keep things modular and reusable,
   82: especially across larger systems or in situations where you want user-selectable behaviour.
   83:

  108: =head3 CONFIGURATION INHERITANCE
  109: 
  110: C<Object::Configure> supports configuration inheritance, allowing child classes to inherit and override configuration settings from their parent classes.
  111: When a class is configured, the module automatically traverses the inheritance hierarchy (using C<@ISA>) and loads configuration files for each ancestor class in the chain.
  112: 
  113: Configuration files are loaded in order from the most general (base class) to the most specific (child class), with later files overriding earlier ones. For example, if C<My::Child::Class> inherits from C<My::Parent::Class>, which inherits from C<My::Base::Class>, the module will:
  114: 
  115: =over 4
  116: 
  117: =item 1. Load C<my-base-class.yml> (or .conf, .json, etc.) if it exists
  118: 
  119: =item 2. Load C<my-parent-class.yml> if it exists, overriding base settings
  120: 
  121: =item 3. Load C<my-child-class.yml>, overriding both parent and base settings
  122: 
  123: =back
  124: 
  125: The configuration files should be named using lowercase versions of the class name with C<::> replaced by hyphens (C<->).
  126: For example, C<My::Parent::Class> would use C<my-parent-class.yml>.
  127: 
  128: This allows you to define common settings in a base class configuration file and selectively override them in child class configurations, promoting DRY (Don't Repeat Yourself) principles and making it easier to manage configuration across class hierarchies.
  129: 
  130: Example:
  131: 
  132:     # File: ~/.conf/my-base-class.yml
  133:     ---
  134:     My__Base__Class:
  135:       timeout: 30
  136:       retries: 3
  137:       log_level: info
  138: 
  139:     # File: ~/.conf/my-child-class.yml
  140:     ---
  141:     My__Child__Class:
  142:       timeout: 60
  143:       # Inherits retries: 3 and log_level: info from parent
  144: 
  145:     # Result: Child class gets timeout=60, retries=3, log_level=info
  146: 
  147: Parent configuration files are optional.
  148: If a parent class's configuration file doesn't exist, the module simply skips it and continues up the inheritance chain.
  149: All discovered configuration files are tracked in the C<_config_files> array for hot reload support.
  150: 
  151: =head3 UNIVERSAL CONFIGURATION
  152: 
  153: All Perl classes implicitly inherit from C<UNIVERSAL>.
  154: C<Object::Configure> takes advantage of this to provide a mechanism for universal configuration settings
  155: that apply to all classes by default.
  156: 
  157: If you create a configuration file named C<universal.yml> (or C<universal.conf>, C<universal.json>, etc.)
  158: in your configuration directory,
  159: the settings in its C<UNIVERSAL> section will be inherited by all classes that use C<Object::Configure>,
  160: unless explicitly overridden by class-specific configuration files.
  161: 
  162: This is particularly useful for setting application-wide defaults such as logging levels,
  163: timeout values,
  164: or other common parameters that should apply across all modules.
  165: 
  166: Example C<~/.conf/universal.yml>:
  167: 
  168:     ---
  169:     UNIVERSAL:
  170:       timeout: 30
  171:       retries: 3
  172:       logger:
  173:         level: info
  174: 
  175: With this universal configuration file in place,
  176: all classes will inherit these default values.
  177: Individual classes can override any of these settings in their own configuration files:
  178: 
  179: Example C<~/.conf/my-special-class.yml>:
  180: 
  181:     ---
  182:     My__Special__Class:
  183:       timeout: 120
  184:       # Inherits retries: 3 and logger.level: info from UNIVERSAL
  185: 
  186: The universal configuration is loaded first in the inheritance chain,
  187: followed by parent class configurations,
  188: and finally the specific class configuration,
  189: with later configurations overriding earlier ones.

  191: =head2 CHANGING BEHAVIOUR AT RUN TIME
  192: 
  193: =head3 USING A CONFIGURATION FILE
  194: 
  195: To control behavior at runtime, C<Object::Configure> supports loading settings from a configuration file via L<Config::Abstraction>.
  196: 
  197: A minimal example of a config file (C<~/.conf/local.conf>) might look like:
  198: 
  199:    [My__Module]
  200:    logger.file = /var/log/mymodule.log
  201: 
  202: The C<configure()> function will read this file,
  203: overlay it onto your default parameters,
  204: and initialize the logger accordingly.
  205: 
  206: If the file is not readable and no config_dirs are provided,
  207: the module will throw an error.
  208: To be clear, in this case, inheritance is not followed.
  209: 
  210: This mechanism allows dynamic tuning of logging behavior (or other parameters you expose) without modifying code.

  214: =head3 USING ENVIRONMENT VARIABLES
  215: 
  216: C<Object::Configure> also supports runtime configuration via environment variables,
  217: without requiring a configuration file.
  218: 
  219: Environment variables are read automatically when you use the C<configure()> function,
  220: thanks to its integration with L<Config::Abstraction>.
  221: These variables should be prefixed with your class name, followed by a double colon.
  222: 
  223: For example, to enable syslog logging for your C<My::Module> class,
  224: you could set:
  225: 
  226:     export My__Module__logger__file=/var/log/mymodule.log
  227: 
  228: This would be equivalent to passing the following in your constructor:
  229: 
  230:      My::Module->new(logger => Log::Abstraction->new({ file => '/var/log/mymodule.log' });
  231: 
  232: All environment variables are read and merged into the default parameters under the section named after your class.
  233: This allows centralized and temporary control of settings (e.g., for production diagnostics or ad hoc testing) without modifying code or files.
  234: 
  235: Note that environment variable settings take effect regardless of whether a configuration file is used,
  236: and are applied during the call to C<configure()>.

 1608: =head1 LIMITATIONS
 1609: 
 1610: =over 4
 1611: 
 1612: =item * B<Global singleton state.> C<%_object_registry>, C<%_config_watchers>, and
 1613: C<%_config_file_stats> are package globals.  Two independent subsystems in the same
 1614: process share one hot-reload registry and one SIGUSR1 handler.  There is no
 1615: instance-level isolation.  A proper fix would wrap state in an object and allow
 1616: multiple independent C<Object::Configure> instances, but that would break the
 1617: existing constructor-call API (C<configure($class, \%params)>).
 1618: 
 1619: =item * B<Hot reload is Unix-only.> SIGUSR1 does not exist on Windows.
 1620: All signal-related paths are guarded with C<$^O ne 'MSWin32'>, so the module
 1621: loads on Windows but silently skips hot-reload registration.
 1622: 
 1623: =item * B<configure() is a God function.> At ~120 lines it handles arg validation,
 1624: config-file discovery, MRO walking, multi-file merging, env-var merging, logger
 1625: creation, and hot-reload bookkeeping.  Future versions should decompose this into
 1626: smaller, independently testable units.
 1627: 
 1628: =item * B<_deep_merge reimplements CPAN.> L<Hash::Merge::Simple> or L<Hash::Merge>
 1629: provide tested, feature-complete deep merge.  The internal C<_deep_merge> is 15
 1630: lines and correct for the current use, but does not handle arrayrefs (they are
 1631: replaced wholesale, not merged).  If array-merge semantics are ever needed, switch
 1632: to a CPAN module.
 1633: 
 1634: =item * B<No encapsulation enforcement.> Private helpers (C<_build_logger>,
 1635: C<_get_inheritance_chain>, etc.) are accessible to any caller.  L<Sub::Private>
 1636: (enforce mode) would make accidental external use a compile-time error.  It is not
 1637: added here to avoid a smoker dependency on a less-common module.
 1638: 
 1639: =item * B<configure() signature is positional, instantiate() is named.>  The two
 1640: public constructors have inconsistent calling conventions.  Normalising them to named
 1641: args would require a deprecation cycle.
 1642: 
 1643: =item * B<mro::get_linear_isa and UNIVERSAL.>  Perl's C<mro::get_linear_isa> does
 1644: not include C<UNIVERSAL> in its output unless C<UNIVERSAL> appears explicitly in
 1645: C<@ISA>.  This module appends C<UNIVERSAL> manually so that C<universal.yml> is
 1646: always discovered.  If a future Perl version changes this behaviour the guard
 1647: (C<grep { $_ eq 'UNIVERSAL' }>) remains correct.

 1706:             (config._config_file != empty =>
 1707:                 result in _object_registry(params.class))

 1709: =head2 enable_hot_reload
 1710: 
 1711:     enable_hot_reload: Interval x Callback -> PID
 1712: 
 1713:     Given:
 1714:     - I: set of positive integers (intervals in seconds)
 1715:     - CB: set of code references
 1716:     - PID: set of process identifiers
 1717: 
 1718:     State:
 1719:     - _config_watchers: {pid: PID, callback: CB}
 1720:     - _config_file_stats: F -> Stat
 1721: 
 1722:     Pre-condition:
 1723:     forall interval in I, callback in CB union {empty}:
 1724:         interval >= 1
 1725:         _config_watchers = empty
 1726:         OS != 'MSWin32'
 1727: 
 1728:     Post-condition:
 1729:     forall result in PID:
 1730:         result > 0
 1731:         _config_watchers.pid = result
 1732:         _config_watchers.callback = callback
 1733:         (forall t in Time:
 1734:             (t mod interval = 0) =>
 1735:                 (exists f in dom _config_file_stats:
 1736:                     mtime(f) > _config_file_stats(f).mtime =>
 1737:                         send_signal(SIGUSR1, parent_process)))
 1738:

 1747:     true

 1755: =head2 reload_config
 1756: 
 1757:     reload_config: () -> N
 1758: 
 1759:     State:
 1760:     - _object_registry: C -> seq ObjectRef
 1761:     - ConfigFiles: F -> H
 1762: 
 1763:     Pre-condition:
 1764:     true
 1765: 
 1766:     Post-condition:
 1767:     forall result in N:
 1768:         result = |{obj in flatten(ran _object_registry) |
 1769:                    obj != empty
 1770:                    obj._config_file in dom ConfigFiles}|
 1771:         (forall obj in flatten(ran _object_registry):
 1772:             obj != empty AND obj._config_file in dom ConfigFiles =>
 1773:                 (forall k in dom ConfigFiles(obj._config_file):
 1774:                     k NOT in PrivateKeys =>
 1775:                         obj(k)@post = ConfigFiles(obj._config_file)(k)))
 1776: 
 1777:     where PrivateKeys = {k | k starts with '_'}

 1779: =head2 register_object
 1780: 
 1781:     register_object: C x O -> ()
 1782: 
 1783:     Given:
 1784:     - C: set of class names
 1785:     - O: set of blessed objects
 1786:     - OR: C -> seq WeakRef(O) (object registry)
 1787: 
 1788:     State:
 1789:     - _object_registry: OR
 1790:     - _original_usr1_handler: SignalHandler union {empty}
 1791:     - $SIG{USR1}: SignalHandler
 1792: 
 1793:     Pre-condition:
 1794:     forall class in C, obj in O:
 1795:         class != empty
 1796:         obj != empty
 1797:         blessed(obj) != empty
 1798: 
 1799:     Post-condition:
 1800:     forall class in C, obj in O:
 1801:         exists ref in _object_registry(class):
 1802:             weak(ref) = obj
 1803:         (_original_usr1_handler = empty@pre =>
 1804:             (_original_usr1_handler@post = $SIG{USR1}@pre
 1805:              $SIG{USR1}@post = reload_config_handler))
