   63: =head1 SYNOPSIS
   64: 
   65: The C<Object::Configure> module is a lightweight utility designed to inject runtime parameters into other classes,
   66: primarily by layering configuration and logging support,
   67: when instatiating objects.
   68: 
   69: L<Log::Abstraction> and L<Config::Abstraction> are modules developed to solve a specific need,
   70: runtime configurability without needing to rewrite or hardcode behaviours.
   71: The goal is to allow individual modules to enable or disable features on the fly,
   72: and to do it using whatever configuration system the user prefers,
   73: and to separate run-time configuration from code.
   74: 
   75: Although the initial aim was general configurability,
   76: the primary use case that's emerged has been fine-grained logging control,
   77: more flexible and easier to manage than what you'd typically do with L<Log::Log4perl>.
   78: For example,
   79: you might want one module to log verbosely while another stays quiet,
   80: and be able to toggle that dynamically - without making invasive changes to each module.
   81: 
   82: To tie it all together,
   83: there is C<Object::Configure>.
   84: It sits on L<Log::Abstraction> and L<Config::Abstraction>,
   85: and with just a couple of extra lines in a class constructor,
   86: you can hook in this behaviour seamlessly.
   87: The intent is to keep things modular and reusable,
   88: especially across larger systems or in situations where you want user-selectable behaviour.
   89:

  114: =head3 CONFIGURATION INHERITANCE
  115: 
  116: C<Object::Configure> supports configuration inheritance, allowing child classes to inherit and override configuration settings from their parent classes.
  117: When a class is configured, the module automatically traverses the inheritance hierarchy (using C<@ISA>) and loads configuration files for each ancestor class in the chain.
  118: 
  119: Configuration files are loaded in order from the most general (base class) to the most specific (child class), with later files overriding earlier ones. For example, if C<My::Child::Class> inherits from C<My::Parent::Class>, which inherits from C<My::Base::Class>, the module will:
  120: 
  121: =over 4
  122: 
  123: =item 1. Load C<my-base-class.yml> (or .conf, .json, etc.) if it exists
  124: 
  125: =item 2. Load C<my-parent-class.yml> if it exists, overriding base settings
  126: 
  127: =item 3. Load C<my-child-class.yml>, overriding both parent and base settings
  128: 
  129: =back
  130: 
  131: The configuration files should be named using lowercase versions of the class name with C<::> replaced by hyphens (C<->).
  132: For example, C<My::Parent::Class> would use C<my-parent-class.yml>.
  133: 
  134: This allows you to define common settings in a base class configuration file and selectively override them in child class configurations, promoting DRY (Don't Repeat Yourself) principles and making it easier to manage configuration across class hierarchies.
  135: 
  136: Example:
  137: 
  138:     # File: ~/.conf/my-base-class.yml
  139:     ---
  140:     My__Base__Class:
  141:       timeout: 30
  142:       retries: 3
  143:       log_level: info
  144: 
  145:     # File: ~/.conf/my-child-class.yml
  146:     ---
  147:     My__Child__Class:
  148:       timeout: 60
  149:       # Inherits retries: 3 and log_level: info from parent
  150: 
  151:     # Result: Child class gets timeout=60, retries=3, log_level=info
  152: 
  153: Parent configuration files are optional.
  154: If a parent class's configuration file doesn't exist, the module simply skips it and continues up the inheritance chain.
  155: All discovered configuration files are tracked in the C<_config_files> array for hot reload support.
  156: 
  157: =head3 UNIVERSAL CONFIGURATION
  158: 
  159: All Perl classes implicitly inherit from C<UNIVERSAL>.
  160: C<Object::Configure> takes advantage of this to provide a mechanism for universal configuration settings
  161: that apply to all classes by default.
  162: 
  163: If you create a configuration file named C<universal.yml> (or C<universal.conf>, C<universal.json>, etc.)
  164: in your configuration directory,
  165: the settings in its C<UNIVERSAL> section will be inherited by all classes that use C<Object::Configure>,
  166: unless explicitly overridden by class-specific configuration files.
  167: 
  168: This is particularly useful for setting application-wide defaults such as logging levels,
  169: timeout values,
  170: or other common parameters that should apply across all modules.
  171: 
  172: Example C<~/.conf/universal.yml>:
  173: 
  174:     ---
  175:     UNIVERSAL:
  176:       timeout: 30
  177:       retries: 3
  178:       logger:
  179:         level: info
  180: 
  181: With this universal configuration file in place,
  182: all classes will inherit these default values.
  183: Individual classes can override any of these settings in their own configuration files:
  184: 
  185: Example C<~/.conf/my-special-class.yml>:
  186: 
  187:     ---
  188:     My__Special__Class:
  189:       timeout: 120
  190:       # Inherits retries: 3 and logger.level: info from UNIVERSAL
  191: 
  192: The universal configuration is loaded first in the inheritance chain,
  193: followed by parent class configurations,
  194: and finally the specific class configuration,
  195: with later configurations overriding earlier ones.

  197: =head2 CHANGING BEHAVIOUR AT RUN TIME
  198: 
  199: =head3 USING A CONFIGURATION FILE
  200: 
  201: To control behavior at runtime, C<Object::Configure> supports loading settings from a configuration file via L<Config::Abstraction>.
  202: 
  203: A minimal example of a config file (C<~/.conf/local.conf>) might look like:
  204: 
  205:    [My__Module]
  206:    logger.file = /var/log/mymodule.log

  208: The C<configure()> function will read this file,
  209: overlay it onto your default parameters,
  210: and initialize the logger accordingly.
  211: 
  212: If the file is not readable and no config_dirs are provided,
  213: the module will throw an error.
  214: To be clear, in this case, inheritance is not followed.

  220: =head3 USING ENVIRONMENT VARIABLES
  221: 
  222: C<Object::Configure> also supports runtime configuration via environment variables,
  223: without requiring a configuration file.
  224: 
  225: Environment variables are read automatically when you use the C<configure()> function,
  226: thanks to its integration with L<Config::Abstraction>.
  227: These variables should be prefixed with your class name, followed by a double colon.
  228: 
  229: For example, to enable syslog logging for your C<My::Module> class,
  230: you could set:
  231: 
  232:     export My__Module__logger__file=/var/log/mymodule.log
  233: 
  234: This would be equivalent to passing the following in your constructor:
  235: 
  236:      My::Module->new(logger => Log::Abstraction->new({ file => '/var/log/mymodule.log' });
  237: 
  238: All environment variables are read and merged into the default parameters under the section named after your class.
  239: This allows centralized and temporary control of settings (e.g., for production diagnostics or ad hoc testing) without modifying code or files.
  240: 
  241: Note that environment variable settings take effect regardless of whether a configuration file is used,
  242: and are applied during the call to C<configure()>.

 1653: # Clean up the watcher child and restore signal state on interpreter exit.
 1654: END {
 1655: 	disable_hot_reload();
 1656: 	restore_signal_handlers();
 1657: }

 1671: =head1 LIMITATIONS
 1672: 
 1673: =over 4
 1674: 
 1675: =item * B<Global singleton state.> C<%_object_registry>, C<%_config_watchers>, and
 1676: C<%_config_file_stats> are package globals.  Two independent subsystems in the same
 1677: process share one hot-reload registry and one SIGUSR1 handler.  There is no
 1678: instance-level isolation.  A proper fix would wrap state in an object and allow
 1679: multiple independent C<Object::Configure> instances, but that would break the
 1680: existing constructor-call API (C<configure($class, \%params)>).
 1681: 
 1682: =item * B<Hot reload is Unix-only.> SIGUSR1 does not exist on Windows.
 1683: All signal-related paths are guarded with C<$^O ne 'MSWin32'>, so the module
 1684: loads on Windows but silently skips hot-reload registration.
 1685: 
 1686: =item * B<configure() is a God function.> At ~120 lines it handles arg validation,
 1687: config-file discovery, MRO walking, multi-file merging, env-var merging, logger
 1688: creation, and hot-reload bookkeeping.  Future versions should decompose this into
 1689: smaller, independently testable units.
 1690: 
 1691: =item * B<_deep_merge reimplements CPAN.> L<Hash::Merge::Simple> or L<Hash::Merge>
 1692: provide tested, feature-complete deep merge.  The internal C<_deep_merge> is 15
 1693: lines and correct for the current use, but does not handle arrayrefs (they are
 1694: replaced wholesale, not merged).  If array-merge semantics are ever needed, switch
 1695: to a CPAN module.
 1696: 
 1697: =item * B<No encapsulation enforcement.> Private helpers (C<_build_logger>,
 1698: C<_get_inheritance_chain>, etc.) are accessible to any caller.  L<Sub::Private>
 1699: (enforce mode) would make accidental external use a compile-time error.  It is not
 1700: added here to avoid a smoker dependency on a less-common module.
 1701: 
 1702: =item * B<configure() signature is positional, instantiate() is named.>  The two
 1703: public constructors have inconsistent calling conventions.  Normalising them to named
 1704: args would require a deprecation cycle.
 1705: 
 1706: =item * B<mro::get_linear_isa and UNIVERSAL.>  Perl's C<mro::get_linear_isa> does
 1707: not include C<UNIVERSAL> in its output unless C<UNIVERSAL> appears explicitly in
 1708: C<@ISA>.  This module appends C<UNIVERSAL> manually so that C<universal.yml> is
 1709: always discovered.  If a future Perl version changes this behaviour the guard
 1710: (C<grep { $_ eq 'UNIVERSAL' }>) remains correct.
 1711: 
 1712: =back

 1714: =head1 Formal Specification
 1715: 
 1716: =head2 configure
 1717: 
 1718:     configure: Class x Params -> ConfigHash
 1719: 
 1720:     Given:
 1721:     - C: set of all class names
 1722:     - P: set of all parameter hashes
 1723:     - F: set of all file paths
 1724:     - H: set of all configuration hashes
 1725: 
 1726:     State:
 1727:     - ConfigFiles: F -> H (maps file paths to configuration content)
 1728:     - EnvVars: String -> String (environment variables)
 1729:     - InheritanceChain: C -> seq C (ordered sequence of ancestor classes)
 1730: 
 1731:     Pre-condition:
 1732:     forall class in C, params in P:
 1733:         class != empty
 1734:         (params.config_file != empty =>
 1735:             (exists dir in params.config_dirs: readable(dir/params.config_file))
 1736:             OR readable(params.config_file))
 1737: 
 1738:     Post-condition:
 1739:     forall result in H:
 1740:         result = params
 1741:                  (+) (merge f in InheritanceConfigFiles(class): ConfigFiles(f))
 1742:                  (+) (merge v in RelevantEnvVars(class): v)
 1743:         result.logger in Log::Abstraction
 1744:         (forall k in dom params:
 1745:             (params(k) in CodeRef OR blessed(params(k))) => result(k) = params(k))
 1746: 
 1747:     where (+) denotes hash merge with right-precedence
 1748: 
 1749: =head2 instantiate
 1750: 
 1751:     instantiate: Params -> Object
 1752: 
 1753:     Given:
 1754:     - P: set of all parameter hashes
 1755:     - C: set of all class names
 1756:     - O: set of all objects
 1757: 
 1758:     Pre-condition:
 1759:     forall params in P:
 1760:         params.class in C
 1761:         params.class.can('new')
 1762: 
 1763:     Post-condition:
 1764:     forall result in O:
 1765:         exists config in H:
 1766:             config = configure(params.class, params)
 1767:             result = params.class.new(config)
 1768:             blessed(result) = params.class
 1769:             (config._config_file != empty =>
 1770:                 result in _object_registry(params.class))
 1771: 
 1772: =head2 enable_hot_reload
 1773: 
 1774:     enable_hot_reload: Interval x Callback -> PID
 1775: 
 1776:     Given:
 1777:     - I: set of positive integers (intervals in seconds)
 1778:     - CB: set of code references
 1779:     - PID: set of process identifiers
 1780: 
 1781:     State:
 1782:     - _config_watchers: {pid: PID, callback: CB}
 1783:     - _config_file_stats: F -> Stat
 1784: 
 1785:     Pre-condition:
 1786:     forall interval in I, callback in CB union {empty}:
 1787:         interval >= 1
 1788:         _config_watchers = empty
 1789:         OS != 'MSWin32'
 1790: 
 1791:     Post-condition:
 1792:     forall result in PID:
 1793:         result > 0
 1794:         _config_watchers.pid = result
 1795:         _config_watchers.callback = callback
 1796:         (forall t in Time:
 1797:             (t mod interval = 0) =>
 1798:                 (exists f in dom _config_file_stats:
 1799:                     mtime(f) > _config_file_stats(f).mtime =>
 1800:                         send_signal(SIGUSR1, parent_process)))
 1801: 
 1802: =head2 disable_hot_reload
 1803: 
 1804:     disable_hot_reload: () -> ()
 1805: 
 1806:     State:
 1807:     - _config_watchers: {pid: PID, callback: CB}
 1808: 
 1809:     Pre-condition:
 1810:     true
 1811: 
 1812:     Post-condition:
 1813:     _config_watchers = empty
 1814:     (forall p in PID:
 1815:         p = _config_watchers.pid@pre =>
 1816:             NOT alive(p))
 1817: 
 1818: =head2 reload_config
 1819: 
 1820:     reload_config: () -> N
 1821: 
 1822:     State:
 1823:     - _object_registry: C -> seq ObjectRef
 1824:     - ConfigFiles: F -> H
 1825: 
 1826:     Pre-condition:
 1827:     true
 1828: 
 1829:     Post-condition:
 1830:     forall result in N:
 1831:         result = |{obj in flatten(ran _object_registry) |
 1832:                    obj != empty
 1833:                    obj._config_file in dom ConfigFiles}|
 1834:         (forall obj in flatten(ran _object_registry):
 1835:             obj != empty AND obj._config_file in dom ConfigFiles =>
 1836:                 (forall k in dom ConfigFiles(obj._config_file):
 1837:                     k NOT in PrivateKeys =>
 1838:                         obj(k)@post = ConfigFiles(obj._config_file)(k)))
 1839: 
 1840:     where PrivateKeys = {k | k starts with '_'}
 1841: 
 1842: =head2 register_object
 1843: 
 1844:     register_object: C x O -> ()
 1845: 
 1846:     Given:
 1847:     - C: set of class names
 1848:     - O: set of blessed objects
 1849:     - OR: C -> seq WeakRef(O) (object registry)
 1850: 
 1851:     State:
 1852:     - _object_registry: OR
 1853:     - _original_usr1_handler: SignalHandler union {empty}
 1854:     - $SIG{USR1}: SignalHandler
 1855: 
 1856:     Pre-condition:
 1857:     forall class in C, obj in O:
 1858:         class != empty
 1859:         obj != empty
 1860:         blessed(obj) != empty
 1861: 
 1862:     Post-condition:
 1863:     forall class in C, obj in O:
 1864:         exists ref in _object_registry(class):
 1865:             weak(ref) = obj
 1866:         (_original_usr1_handler = empty@pre =>
 1867:             (_original_usr1_handler@post = $SIG{USR1}@pre
 1868:              $SIG{USR1}@post = reload_config_handler))
 1869:

 1872:     restore_signal_handlers: () -> ()
 1873: 
 1874:     State:
 1875:     - _original_usr1_handler: SignalHandler union {empty}
 1876:     - $SIG{USR1}: SignalHandler
 1877: 
 1878:     Pre-condition:
 1879:     true
 1880: 
 1881:     Post-condition:
 1882:     $SIG{USR1}@post = _original_usr1_handler@pre
 1883:     _original_usr1_handler@post = empty
