   53: 
   54: Object::Configure - Runtime Configuration for an Object

   64: =head1 DESCRIPTION
   65: 
   66: C<Object::Configure> injects runtime configuration and logging into Perl class
   67: constructors.  It is a thin layer on top of L<Config::Abstraction> (reads config
   68: files and environment variables) and L<Log::Abstraction> (logging).
   69: 
   70: Call C<configure($class, \%params)> at the start of your C<new()> method.  It:
   71: 
   72: =over 4
   73: 
   74: =item 1. Walks C<@ISA> and finds config files for every class in the inheritance chain.
   75: 
   76: =item 2. Merges those files, then overlays environment variables named C<ClassName__key>.
   77: 
   78: =item 3. Creates a L<Log::Abstraction> logger and stores it in C<$params-E<gt>{logger}>.
   79: 
   80: =item 4. Returns a hashref ready to pass to C<bless>.
   81: 
   82: =back
   83: 
   84: The module also provides optional hot-reload support: a background process watches
   85: config files and sends C<SIGUSR1> to trigger an in-place update of registered objects
   86: without restarting the application.
   87: 
   88: B<Hot reload is not supported on Windows> (C<SIGUSR1> does not exist there).
   89:

  203: =head1 CONFIGURATION
  204: 
  205: =head2 Config file naming
  206: 
  207: The config file name is derived from the class name by lowercasing it and replacing
  208: C<::> with hyphens (C<->):
  209: 
  210:     My::Parent::Class  =>  my-parent-class.yml
  211: 
  212: The file is searched for in the directory of the C<config_file> argument, then in
  213: any directories listed in C<config_dirs>.
  214: 
  215: =head2 Section key naming inside the config file
  216: 
  217: Inside the YAML (or JSON or conf) file, the section key uses double underscores in
  218: place of C<::>:
  219: 
  220:     # my-parent-class.yml
  221:     ---
  222:     My__Parent__Class:
  223:       timeout: 30
  224:       retries: 3
  225: 
  226: =head2 Configuration resolution order
  227: 
  228: The following sources are merged from I<lowest> to I<highest> priority.  A value
  229: from a higher-priority source always wins over a lower-priority one.
  230: 
  231: =over 4
  232: 
  233: =item 1. B<Caller-supplied params> -- the hashref you pass to C<configure()>.  Despite
  234: the name "defaults", these are the I<lowest> priority and are overridden by everything
  235: else.
  236: 
  237: =item 2. B<UNIVERSAL section> -- the C<UNIVERSAL:> block in C<universal.yml> (or
  238: C<universal.conf>, C<universal.json>) in your config directories, if the file exists.
  239: 
  240: =item 3. B<Ancestor class config files> -- walked base-first through C<@ISA> using
  241: the class's Method Resolution Order (MRO).
  242: 
  243: =item 4. B<Primary config file> -- the file named by the C<config_file> argument.
  244: 
  245: =item 5. B<Environment variables> -- named C<ClassName__key=value>, where C<::> in
  246: the class name is replaced by C<__>.  These are the I<highest> priority.
  247: 
  248: =back
  249: 
  250: =head2 UNIVERSAL configuration
  251: 
  252: If you create C<universal.yml> in your config directory with a C<UNIVERSAL:> section,
  253: those settings apply to every class that uses C<Object::Configure> unless a
  254: more-specific source overrides them:
  255: 
  256:     # ~/.conf/universal.yml
  257:     ---
  258:     UNIVERSAL:
  259:       timeout: 30
  260:       logger:
  261:         level: warning
  262: 
  263: =head2 Logging
  264: 
  265: C<configure()> always sets C<$params-E<gt>{logger}> to a L<Log::Abstraction>
  266: instance.  You can control it by passing a C<logger> key:
  267: 
  268:     # Arrayref: messages are captured into @log (protected from merge override)
  269:     configure($class, { logger => \@log });
  270: 
  271:     # Hashref: options forwarded to Log::Abstraction::new()
  272:     configure($class, { logger => { level => 'debug', file => '/var/log/app.log' } });
  273: 
  274:     # String 'NULL': disables all logging
  275:     configure($class, { logger => 'NULL' });
  276: 
  277:     # Existing Log::Abstraction object: used as-is
  278:     configure($class, { logger => $my_logger });
  279: 
  280: B<Note:> only arrayref loggers are stashed before the config merge and are guaranteed
  281: to survive it.  C<'NULL'> and blessed logger objects can be overridden by a
  282: C<UNIVERSAL:> section in C<universal.yml>.  See L</COMMON PITFALLS>.
  283: 
  284: =head2 Environment variable format
  285: 
  286: Environment variable names are constructed as:
  287: 
  288:     ClassName__key
  289: 
  290: where C<::> in the class name is replaced by two underscores.
  291: 
  292:     export My__Module__timeout=60
  293:     export My__Module__logger__level=debug

  295: =head1 HOT RELOAD
  296: 
  297: Hot reload lets you edit a config file and have all live objects update themselves
  298: without restarting the program.
  299: 
  300: =head2 How it works
  301: 
  302: =over 4
  303: 
  304: =item 1. Your constructor calls C<register_object($class, $self)> to opt in.
  305: 
  306: =item 2. Your main program calls C<enable_hot_reload()> to fork a background watcher.
  307: 
  308: =item 3. The watcher polls config files every C<interval> seconds and sends
  309: C<SIGUSR1> to the parent when it detects a change.
  310: 
  311: =item 4. The C<SIGUSR1> handler calls C<reload_config()>, which re-reads files and
  312: updates every registered object in-place.
  313: 
  314: =item 5. Your main program calls C<disable_hot_reload()> on shutdown.
  315: 
  316: =back
  317: 
  318: Private keys (those whose names start with C<_>) are never overwritten during
  319: reload, so internal bookkeeping is safe.
  320: 
  321: B<Hot reload is not supported on Windows.>
  322: 
  323: =head1 COMMON PITFALLS
  324: 
  325: =head2 Only arrayref loggers survive the config merge
  326: 
  327: If you pass C<logger =E<gt> 'NULL'> or C<logger =E<gt> $existing_logger>, the
  328: C<UNIVERSAL:> section in C<universal.yml> (or a site-local config file) can
  329: silently override your logger during the config merge.
  330: 
  331: Only arrayref loggers are stashed before the merge and are guaranteed to survive:
  332: 
  333:     # Protected -- will NOT be overridden by universal.yml
  334:     configure($class, { logger => \@captured });
  335: 
  336:     # NOT protected -- universal.yml can override these
  337:     configure($class, { logger => 'NULL' });
  338:     configure($class, { logger => $existing_obj });
  339: 
  340: =head2 Caller-supplied keys are the LOWEST priority
  341: 
  342: Despite being called "defaults", keys you pass directly to C<configure()> are
  343: overridden by config files and environment variables:
  344: 
  345:     # My__Module__timeout=60 is set in the shell.
  346:     # $params->{timeout} will be 60, not 30.
  347:     configure('My::Module', { timeout => 30 });
  348: 
  349: Use caller-supplied keys only as a last-resort fallback.
  350: 
  351: =head2 register_object() pushes; it does not replace
  352: 
  353: Calling C<register_object()> twice for the same class registers B<two> entries.
  354: Both objects receive updates on every reload.  The second call does not remove the
  355: first.
  356: 
  357:     Object::Configure::register_object('My::Class', $obj_a);
  358:     Object::Configure::register_object('My::Class', $obj_b);
  359:     # reload_config() now updates BOTH $obj_a and $obj_b
  360: 
  361: =head2 Private keys are never updated on hot reload
  362: 
  363: Any key whose name begins with C<_> is skipped during C<reload_config()>.
  364: A config key named C<_my_setting> in your YAML file will be ignored at reload time.
  365: 
  366: =head2 The 'class' key appears on objects created by instantiate()
  367: 
  368: C<instantiate()> intentionally leaves the C<class> key in the hashref passed to
  369: C<$class-E<gt>new()> as a debugging aid.  Your object will have a C<class>
  370: attribute set to the class name:
  371: 
  372:     my $obj = Object::Configure::instantiate(class => 'My::Thing', ...);
  373:     print $obj->{class};    # prints 'My::Thing'
  374: 
  375: =head2 Memoization caches are not invalidated during a run
  376: 
  377: C<_get_inheritance_chain()> and C<_find_class_config_file()> cache their results
  378: for the lifetime of the process.  If you alter C<@ISA> or add config files after
  379: the first C<configure()> call for a given class, the cache returns stale results.
  380: 
  381: =head2 disable_hot_reload() blocks for up to five seconds
  382: 
  383: It waits for the watcher process to exit (SIGTERM first, then SIGKILL).  Do not
  384: call it from inside a signal handler or a timing-sensitive loop.
  385: 
  386: =head2 config_file must be developer-controlled
  387: 
  388: The C<config_file> path is validated against directory traversal (C<../>) but is
  389: not otherwise restricted.  It must always be a developer-supplied path, never raw
  390: user input.

 1745: =head1 LIMITATIONS
 1746: 
 1747: =over 4
 1748: 
 1749: =item * B<Global singleton state.> C<%_object_registry>, C<%_config_watchers>, and
 1750: C<%_config_file_stats> are package globals.  Two independent subsystems in the same
 1751: process share one hot-reload registry and one SIGUSR1 handler.  There is no
 1752: instance-level isolation.  A proper fix would wrap state in an object and allow
 1753: multiple independent C<Object::Configure> instances, but that would break the
 1754: existing constructor-call API (C<configure($class, \%params)>).
 1755: 
 1756: =item * B<Hot reload is UNIX-only.> SIGUSR1 does not exist on Windows.
 1757: All signal-related paths are guarded with C<$^O ne 'MSWin32'>, so the module
 1758: loads on Windows but silently skips hot-reload registration.
 1759: 
 1760: =item * B<configure() is a God function.> At ~120 lines it handles arg validation,
 1761: config-file discovery, MRO walking, multi-file merging, env-var merging, logger
 1762: creation, and hot-reload bookkeeping.  Future versions should decompose this into
 1763: smaller, independently testable units.
 1764: 
 1765: =item * B<_deep_merge reimplements CPAN.> L<Hash::Merge::Simple> or L<Hash::Merge>
 1766: provide tested, feature-complete deep merge.  The internal C<_deep_merge> is 15
 1767: lines and correct for the current use, but does not handle arrayrefs (they are
 1768: replaced wholesale, not merged).  If array-merge semantics are ever needed, switch
 1769: to a CPAN module.
 1770: 
 1771: =item * B<No encapsulation enforcement.> Private helpers (C<_build_logger>,
 1772: C<_get_inheritance_chain>, etc.) are accessible to any caller.  L<Sub::Private>
 1773: (enforce mode) would make accidental external use a compile-time error.  It is not
 1774: added here to avoid a smoker dependency on a less-common module.
 1775: 
 1776: =item * B<configure() signature is positional, instantiate() is named.>  The two
 1777: public constructors have inconsistent calling conventions.  Normalising them to named
 1778: args would require a deprecation cycle.
 1779: 
 1780: =item * B<mro::get_linear_isa and UNIVERSAL.>  Perl's C<mro::get_linear_isa> does
 1781: not include C<UNIVERSAL> in its output unless C<UNIVERSAL> appears explicitly in
 1782: C<@ISA>.  This module appends C<UNIVERSAL> manually so that C<universal.yml> is
 1783: always discovered.  If a future Perl version changes this behaviour the guard
 1784: (C<grep { $_ eq 'UNIVERSAL' }>) remains correct.
 1785:
